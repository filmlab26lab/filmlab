# 03 正式版界面（v0.2.0）

这一版把 0.1.0 的单页测试界面换成了正式结构：首页两个入口、左上角设置、照片链路真能用。
包里仍然是**未签名 IPA**，装之前必须先在爱思助手签一次（见 `02_签名与安装步骤.md`）。

## 一、屏幕结构

```
首页 HomeView
├─ 左上角：设置（齿轮带细描边的圆形按钮，右上角是版本号）
├─ 主体：FilmLab + 负片·染料·相纸 + 当前默认预设
├─ 胶片齿孔装饰条
├─ 新建照片项目  → PhotoProjectView
├─ 新建视频项目  → VideoProjectView
└─ 页脚：链路名 + 四要素

设置 SettingsView（sheet）
├─ 新建项目的默认预设（四选一，全 App 持久化）
├─ 引擎说明（Halation / 密度联动颗粒 / 色彩密度 / 分段曲线）
├─ 开发 → 链路自检（0.1.0 那套设备与 Log 自检页保留）
└─ 关于（版本、本地渲染无联网、曲线为锚点近似）

照片项目 PhotoProjectView
├─ 预览（Metal 实时；没选照片时显示着色器内置测试色卡）
├─ 预设条：标准 / 暖调 / 高密度 / 清淡
├─ 参数：胶片强度、颗粒、Halation、色彩密度、输入色彩空间
├─ 选择照片（系统 PhotosPicker）、复位
└─ 右上角「导出」→ 离屏渲染 → 写相册

视频项目 VideoProjectView
├─ 工程规格：时长（3–30 秒）、帧率（24/25/30）、画幅（16:9 / 9:16 / 1:1）、输入 Log
├─ 片段空态（虚线框）
├─ 这一版有什么、没什么（四行清单）
└─ 添加片段（弹提示，明确说明下一版接）
```

## 二、视觉规范（改配色只改 `Theme.swift`）

| 用途 | 值 |
|---|---|
| 相纸底 `FL.paper` | #F4EFE7 |
| 纸暗部 `FL.paperDeep` | #E8E1D8 |
| 墨色字 `FL.ink` | #1B1916 |
| 次要字 `FL.inkSoft` | 墨色 52% |
| 胶片橙 `FL.ochre` | #C4631F |
| 卡片底 `FL.card` | #FCFAF6 |

规则：

- 字体：标题用 serif（`FL.titleFont` 32pt），正文系统字体，数值一律等宽字体（`FL.monoFont`）。
- 卡片：圆角 18、1px 细描边、很轻的投影，统一走 `.filmCard()`。
- 胶片橙只给关键数值和主按钮，一屏不超过三处 —— 多了就变成滤镜风而不是胶片风。
- 底纹是确定性噪点（`GrainOverlay`），不用随机数，避免界面自己「呼吸」。
- 强制浅色（`preferredColorScheme(.light)`）：这套配色在深色模式下会散架。

## 三、这一版真正可用的 / 还没接的

可用：

- 选一张照片 → 实时套胶片管线（Metal 逐帧渲染）→ 调四个参数和 Log 输入 → 导出到相册
- 预设一键套用，设置里的默认预设会影响新建项目
- 链路自检页仍在，可核对「四种 Log 模式画面应一致」

没接：

- 视频：帧解码、逐帧渲染、音轨、导出（页面已把规格与结构定好，按钮弹提示，不做假功能）
- 照片的工程保存/历史记录（现在是「调完即导出」）
- Log 曲线的厂商精确系数（仍为公开资料锚点近似，上架前必须替换）

# 五、v0.3.0 追加（画面调整 / 底片型号 / 导入导出修复 / 视频接真）

这一版起因是 v0.2.0 在真机上的三个实测问题：
「导入照片看不到实时调色」、「没有底片型号可选」、「视频页只是个骨架」。

## 1. 照片页（PhotoProjectView 重写）

预览换成 **后台串行队列离屏渲染 + Image 显示**（`PreviewRenderer`，长边 900，滑块 debounce 120ms）。
不再用 MTKView 做照片预览 —— 那条路径的「黑屏 / 首帧不刷新 / 纹理载入失败」正好是用户看到的现象。

- 导入：`PhotosPicker` → `loadTransferable(Data)` → `UIImage` → `flNormalizedUp()` 摆正 EXIF 方向。
- 纹理：**不再用 MTKTextureLoader**（对 P3 / 16bit 的相册 CGImage 会抛错），改 `FilmRenderer.makeTexture` 自己 `CGContext` 画进 `bgra8Unorm`。
- 裁剪：预览显示**未裁剪整幅**并叠 `CropOverlay`（四块暗化遮罩 + 三分线 + 拖动移框 + 右下角手柄锁比例缩放）；
  比例条七档：自由 / 16:9 / 9:16 / 4:3 / 3:4 / 1:1 / 2.35:1；另有「裁剪大小」与「水平 / 垂直」微调。
  导出按 crop 渲染（长边 2200），所以**框里看到的就是导出的**。
- 底片：横向 chips，10 款（中性原片 / 柯达 Portra 400·800·Gold 200·Ektar 100·Tri-X / 富士 Pro 400H·Superia 400·C200 / 依尔福 HP5）。
- 参数：强度、颗粒、Halation、色彩密度、色温、色偏、饱和度 + Log 输入 + 四个预设力度。
- 导出：`UIImageWriteToSavedPhotosAlbum`，成功弹「已存到相册」。

## 2. 视频页（版式按用户要求重排）

顺序改成 **片段在最上面，其余（预览 / 画面与调节 / 底片 / 导出）都在下面**：

```
片段（列表 + 删除 + 导入视频）
预览（逐帧过管线，播放/暂停，左下角显示输出尺寸）
画面与调节（比例条 + 预设 + 七个参数 + Log）
底片（10 款 chips）
导出（进度条 + 存相册）
```

- 导入：`VideoFile: Transferable`（`FileRepresentation(contentType: .movie)` 拷进临时目录），`VideoClip.make` 读出显示尺寸、旋转变换、时长。
- 实时预览：`AVPlayerItemVideoOutput` 每帧取 `CVPixelBuffer` → `CVMetalTextureCache` → 同一个 `FilmRenderer` 渲染到 `MTKView`。
  **改参数画面立刻变**，不是给画面盖色片。
- 旋转变换：着色器新增 `rotateQuarter`，用整数映射把「显示方向 uv」转回「源画面 uv」，竖拍视频不会躺倒。
- 导出：`AVAssetReader`（BGRA 逐帧）→ Metal 渲染到目标纹理 → `getBytes` 抄进 `AVAssetWriterInputPixelBufferAdaptor` 的 CVPixelBuffer → H.264 重编码；
  音频走旁路透传（`AVAssetReaderTrackOutput` settings=nil → `AVAssetWriterInput` settings=nil）。
  输出尺寸 = 显示尺寸 × 裁剪比例，强制偶数；进度条按已写帧数估。

## 3. 着色器/引擎改动

`Uniforms` 扩到 16 个 4 字节槽（`time` … `chroma` + `int rotateQuarter`），对应 `FilmUniforms` 同步改：
新增裁剪窗口（cropX/Y/W/H）、色温、色偏、饱和度、旋转。片元先「显示 uv → 裁剪窗口 → 旋转回源坐标」再采样，
颗粒坐标用裁剪后的 uv，换框时颗粒不会跟着漂。

## 4. 这一版已知的边界（都要靠真机反馈再收）

- 视频导出整条管线**无法在 Windows 本地验证**，只有云端能保证「编得过」，运行正确性靠真机；
- 音轨是旁路透传（原样搬运，不重采样）：遇到个别素材可能导出后无声，属于已知风险点；
- 视频裁剪是「按比例居中裁」，暂不支持在画面上拖框（照片页才有自由拖框）；
- 视频片段只活在本次会话里，退出 App 不保存（工程保存/历史记录仍未做）；
- Log 曲线仍是公开资料锚点近似，上架前必须替换成厂商规范数值。
